# نسخه Tkinter سامانه مدیریت درخواست‌های تعمیرات

این پوشه نسخه جدید مبتنی بر Tkinter است و به فایل‌های نسخه PySide6 در ریشه پروژه دست نمی‌زند.

## اجرا

از پوشه اصلی پروژه و در محیط Python ۳۲ بیتی:

```powershell
python -m tk_version.app
```

وابستگی‌های اصلی برنامه:

```powershell
python -m pip install pyodbc python-dotenv jdatetime jalali-core openpyxl et-xmlfile arabic-reshaper python-bidi
```

Tkinter همراه نصب استاندارد Python ویندوز ارائه می‌شود. درایور Microsoft Access ODBC باید با معماری Python/برنامه (۳۲ یا ۶۴ بیت) روی رایانه نصب باشد.

## امکانات منتقل‌شده

- ورود کاربران از جدول `tbluser` با حفظ بررسی رمزهای PBKDF2 و رمزهای قدیمی.
- پوسته اصلی و منوی فارسی.
- ثبت درخواست تعمیرات در جدول `tblkar`.
- تولید شماره درخواست بر اساس بیشترین `wonumber` موجود.
- ذخیره تاریخ درخواست به‌صورت عدد شمسی `YYYYMMDD` و نمایش `YYYY/MM/DD`.
- محدودیت ثبت و مشاهده بر اساس سطح دسترسی و واحد کاربر.
- مشاهده فهرست درخواست‌ها، جست‌وجو و فیلتر بر اساس موضوع.
- نمایش وضعیت و آخرین اطلاعات پیگیری موجود در `tblkar`.
- خروجی Excel از فهرست فیلترشده.

## نکات دیتابیس

اتصال از طریق `db_config.py` و فایل `.env` ریشه پروژه انجام می‌شود. مسیر شبکه دیتابیس Access باید از رایانه مقصد قابل دسترسی باشد و درایور ODBC هم‌معماری با Python نصب شده باشد.

در فرم ثبت، ستون‌های اصلی `tblkar` استفاده می‌شوند. ستون‌های تکمیلی وضعیت و پیگیری با توجه به ساختار موجود جدول شناسایی می‌شوند؛ در صورت عدم امکان خواندن metadata، نام‌های سازگار با نسخه قبلی (`vaziyat`, `payan`, `tarikh`, `editor`, `sharhepey`) به کار می‌روند.

## وضعیت انتقال

صفحه ثبت و مشاهده درخواست‌های تعمیرات منتقل شده است. بخش‌های گزارش مستقل، پیگیری/ویرایش وضعیت، اموال، مهمانسرا، لوازم‌التحریر، مدیریت کاربران و تنظیمات ظاهر هنوز در مراحل بعدی منتقل خواهند شد.

برای متن‌های نمایشی از `arabic-reshaper` و `python-bidi` استفاده می‌شود. رفتار راست‌به‌چپ، به‌ویژه در فیلدهای قابل ویرایش و جدول‌ها، باید روی Windows و فونت‌های مقصد آزمایش شود؛ Tkinter برخلاف Qt پشتیبانی RTL کاملاً بومی و یکپارچه ندارد.
